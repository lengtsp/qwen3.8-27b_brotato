หลายคนคงเคยเห็น AI สร้างเกมกันแล้ว คราวนี้ลองให้ AI เล่นเกมให้ด้วยซะเลย 🎮🤖

ผมกำลังพัฒนา AI agent สำหรับควบคุม Brotato จากภาพหน้าจอจริง ให้ระบบวางแผนเดิน เก็บไอเท็ม หลบอันตราย และรักษา HP แล้วดูผลเพื่อปรับแผนต่อ

โจทย์ที่สนใจคือ เราจะทำให้โมเดลที่มีอยู่แล้วควบคุมเกมได้ดีขึ้นผ่านการรับรู้ภาพ การวางแผน และความจำ โดยยังไม่ fine-tune น้ำหนักของ Qwen ได้แค่ไหน?

🎯 เริ่มจากวงจรควบคุมที่ตอบสนองต่อเกมจริง

Capture ภาพ → อ่าน HUD และตรวจตำแหน่ง → วางแผนเส้นทาง → ตรวจความเสี่ยง → ส่งปุ่ม → ดูผล → ปรับแผน

ระบบใช้ Qwen ผ่าน vLLM ร่วมกับ Simple-JEV เพื่อประเมินฉากและตัวเลือกการเคลื่อนไหว ทำงานคู่กับ CPU ที่ตรวจภาพล่าสุด เส้นทาง และจังหวะส่งปุ่ม รองรับ 8 ทิศทาง รวมการเดินเฉียง

Simple-JEV เป็นเครื่องมือ structured classification/scoring ที่ใช้ในระบบ แยกจากงานวิจัยที่นำมาเป็นแนวคิดด้านล่าง
https://github.com/featherless-ai/simple-jev

🔧 ใช้เทคนิคอะไร และช่วยแก้ปัญหาตรงไหน?

• Asynchronous fast/slow control + latest-frame queue
แยกการประเมินของโมเดลออกจากการส่งปุ่ม และแทนภาพที่รอประมวลผลด้วยภาพล่าสุด ช่วยไม่ให้ต้องรอคำตอบโมเดลใหม่ทุกปุ่มหรือสะสมคิวภาพเก่า ทั้งนี้ ต้องตรวจภาพและเส้นทางปัจจุบันก่อนส่งปุ่มเสมอ

• Goal commitment / hysteresis + main/backup plan
รักษาเป้าหมายเก็บของที่ยังมีอยู่ ใช้การค้นเส้นทางบน grid และ A* สำหรับทางอ้อม แล้วเตรียมทางหลักกับทางสำรองจากภาพปัจจุบัน สิ่งที่เพิ่มคือการอ้อมอันตรายแล้วยังมุ่งกลับเป้าหมายเดิม แทนการเปลี่ยนเป้าถี่จนไม่คืบหน้า ส่วนจะเก็บของได้มากขึ้นเท่าไรยังต้องวัดในเกมจริง

• Temporal tracking + projectile path prediction
เชื่อมวัตถุจากภาพล่าสุดที่จับคู่ได้ แล้วคาดแนวกระสุนระยะสั้นเพื่อตรวจว่ากำลังจะตัดเส้นทางเดินหรือไม่ เคสจำลองตรวจได้ว่าระบบปิดทางที่กระสุนจะตัดหน้า แม้กระสุนยังไม่ใกล้ชนตัวผู้เล่นที่ยืนนิ่ง แต่ยังไม่ใช่หลักฐานว่าเสีย HP น้อยลงในเกมจริง

• แยกตำแหน่งตัวผู้เล่นจากอาวุธ + ควบคุม 8 ทิศทาง
เพิ่มการตรวจรูปร่างตัวผู้เล่นที่ไม่ต้องอาศัยตำแหน่งอาวุธ และใช้ปุ่มคู่สำหรับเดินเฉียง เพิ่มทางเลือกให้หลบและเข้าหาเป้าหมายได้ละเอียดขึ้น หากยังแยกตัวผู้เล่นไม่ได้ ระบบจะไม่เดาตำแหน่งจากอาวุธ จำนวนทิศทางที่เพิ่มขึ้นยังไม่ใช่หลักฐานว่าคะแนนสูงขึ้น

• Episodic retrieval + evidence-linked reflection
ค้นประสบการณ์ที่ตรงบริบทมาเป็นคำแนะนำแบบมีขอบเขต และให้ AI ร่างบทเรียนพร้อมหลักฐานหลังจบช่วงควบคุม สิ่งที่เพิ่มคือย้อนตรวจได้ว่าเรียนจากเหตุการณ์ใด และแยกบทเรียนที่ยังไม่ผ่านการทดสอบออกจากการควบคุมจริง ส่วนประโยชน์ต่อคะแนนและ HP ยังต้องทดสอบเทียบกับการปิด memory

• NumPy vectorization + run-based connected components
เร่งงานอ่านสีและรวมกลุ่มพิกเซลบน CPU โดยทำงานเป็นชุดและเชื่อมช่วงพิกเซล แทนการไล่คิวทีละพิกเซลใน Python ผลความเร็วที่วัดได้แสดงแยกไว้ด้านล่าง

🧠 ความจำและการเรียนรู้จากประสบการณ์ อ้างอิงแนวคิดอะไรบ้าง?

1. VideoAgent — จดจำสิ่งที่เห็นตามลำดับเวลา
งานนี้เก็บเหตุการณ์และสถานะการติดตามวัตถุใน structured memory เป็นแนวคิดประกอบการออกแบบประวัติภาพระยะสั้นและความสัมพันธ์ของสิ่งที่เห็นข้ามเฟรม ทั้งนี้ งานต้นฉบับวัดความเข้าใจวิดีโอ ไม่ได้พิสูจน์การหลบกระสุนของโครงการนี้
VideoAgent: A Memory-augmented Multimodal Agent for Video Understanding (2024)
https://arxiv.org/abs/2403.11481

2. JARVIS-1 — ใช้ประสบการณ์เดิมช่วยวางแผน
งานนี้เชื่อมการรับรู้ภาพ ความจำ และการวางแผนใน Minecraft โครงการนี้นำแนวคิดมาประกอบการค้นประสบการณ์ที่เกี่ยวข้องกับสถานการณ์ปัจจุบัน โดยยังให้ภาพและข้อจำกัดปัจจุบันกำหนดการเคลื่อนไหว
JARVIS-1: Open-World Multi-task Agents with Memory-Augmented Multimodal Language Models (2023)
https://arxiv.org/abs/2311.05997

3. Reflexion — ทบทวนผลลัพธ์แล้วเก็บบทเรียนเป็นข้อความ
งานนี้ใช้ feedback และ episodic memory ช่วยการตัดสินใจโดยไม่อัปเดตน้ำหนักโมเดล เป็นแนวคิดประกอบการบันทึกว่าเกิดอะไรขึ้น ลองทำอะไร และควรทดสอบทางเลือกใดต่อ โดยแยกข้อสังเกตออกจากการคาดเดาสาเหตุ
Reflexion: Language Agents with Verbal Reinforcement Learning (2023)
https://arxiv.org/abs/2303.11366

4. Voyager — สะสมทักษะที่นำกลับมาใช้ได้
งานนี้ใช้คลังทักษะและ feedback เพื่อพัฒนา agent ใน Minecraft เป็นแนวคิดประกอบการออกแบบบทเรียนแบบมีเงื่อนไขที่ทดสอบซ้ำและตรวจการถ่ายโอนไปสถานการณ์ใหม่ได้ ส่วนโครงการนี้ยังไม่เปิดให้โค้ดทักษะที่โมเดลสร้างเข้าไปสั่งคีย์บอร์ดโดยตรง
Voyager: An Open-Ended Embodied Agent with Large Language Models (2023)
https://arxiv.org/abs/2305.16291

5. AgentGarten — ฝึกเป็นรอบ ทบทวน แล้วส่งต่อ playbook
งานนี้ศึกษาการฝึก agent ใน code worlds โดยทบทวนแต่ละรอบและส่งต่อบทเรียนให้รอบถัดไป โครงการนี้เลือกปรับแนวคิดด้าน post-segment review และ candidate playbook โดยเก็บบทเรียนที่ร่างไว้ทดสอบแยกก่อนนำไปใช้งาน และไม่ได้สร้าง neural renderer หรือระบบจำลองตามงานต้นฉบับ
AgentGarten: Code Worlds for Evolving Agents (2026)
https://arxiv.org/html/2610.12374v2

งานเหล่านี้เป็นแหล่งแนวคิดคนละส่วน ไม่ได้หมายความว่าโครงการนี้จำลองงานต้นฉบับครบ หรือได้ผลลัพธ์เทียบเท่างานวิจัยเหล่านั้น ส่วน closed-loop control และการแยกวงจรเร็ว/ช้าเป็นหลักวิศวกรรมที่ใช้จัดโครงสร้างตัวควบคุม

🤝 คนยังอยู่ในวงจรตัดสินใจ

ตอนเลือกตัวละคร อาวุธ ความยาก รวมถึง Level up, Shop และเลือกไอเท็ม ยังให้ผู้เล่นตัดสินใจเอง เมื่อกลับสู่ gameplay ระบบจึงตรวจภาพปัจจุบันก่อนรับช่วงควบคุมต่อใน session ที่เปิดใช้งานไว้

📊 จะรู้ได้อย่างไรว่าทำได้ดีขึ้นจริง?

ผมแยกการวัดออกเป็น 4 ส่วน เพื่อให้เห็นว่าความสามารถมาจากตรงไหน
• โมเดล: แยกฉากและเสนอการเคลื่อนไหวได้เหมาะสมเพียงใด รวมถึงเมื่อไรควรตอบว่าไม่แน่ใจ
• Computer Vision: ระบุตัวผู้เล่น วัตถุ และ HUD ได้แม่นเพียงใด
• การตอบสนอง: ใช้เวลาจากภาพต้นทางถึงการส่งปุ่มเท่าไร และมีช่วงหยุดนิ่งมากแค่ไหน โดยไม่ใช้ FPS ของภาพ preview แทนความเร็วการตัดสินใจ
• ผลการเล่น: เก็บของได้เท่าไร เหลือ HP เท่าไร และผ่านหรือแพ้ พร้อมเปรียบเทียบ memory เปิด/ปิด โดยคงโมเดลและตัวควบคุมเหมือนกัน

ผลที่วัดได้แล้วด้านความเร็ว เป็น benchmark แบบ offline replay จากภาพบันทึกเดิมร่วมกับตัวส่งคำสั่งจำลอง ไม่ใช่การทดสอบสดรอบใหม่:
• ค่าเวลางาน CPU มัธยฐาน 123.20 → 78.52 ms ลดลงประมาณ 36%
• ช่วงห่างระหว่างคำสั่งมัธยฐาน 145.41 → 100.99 ms
• จำนวนคำสั่งที่พบช่องว่างตอนต่ออายุการเคลื่อนไหวจำลอง 14 → 0 ในชุดทดสอบเดียวกัน

ชุดนี้มี 25 คำสั่ง และมีข้อมูล timing 23 คำสั่งต่อโหมด ตัวเลขสะท้อนการปรับ pipeline CPU/การต่อคำสั่งในเคสเดิม ไม่ใช่หลักฐานว่า Qwen inference เร็วขึ้น 36% หรือเกมสดจะเดินต่อเนื่องทุกสถานการณ์
ดูผลรวมที่เผยแพร่:
https://github.com/lengtsp/qwen3.8-27b_brotato/blob/main/docs/evidence/continuity-replay-continuity.json

ต้องแยกรอบที่ใช้เรียนรู้ออกจากรอบประเมินผล และรายงานปัจจัยที่ยังควบคุมไม่ได้ เช่น RNG ด้วย

ตอนนี้ผลทดลองเบื้องต้นยังไม่พอสรุปว่า memory ทำให้เล่นดีขึ้น หรือเล่นบ่อยแล้วจะเก่งขึ้นทุกครั้ง เป้าหมายคือทดสอบว่าบทเรียนใดช่วยได้จริง บทเรียนใดควรแก้หรือเลิกใช้ โดยไม่เอาจำนวนความจำที่สะสมมาแทนคะแนนความสามารถ บทเรียนที่ AI ร่างยังไม่ถูกนำไปใช้ควบคุมอัตโนมัติทันที
